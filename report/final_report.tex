{\heiti\zihao{2} 摘要}

大语言模型智能体能够调用命令行、读写文件、抓取网页和访问外部工具，安全风险已经不再局限于模型回答本身，而是延伸到“模型会不会采取危险行动”。本作品围绕“面向大模型及其应用的安全性研究”选题，从红队视角梳理提示注入、模型越狱、训练数据泄露、工具调用劫持、记忆中毒、环境感知污染和间接提示注入等攻击面，并在 Argus 项目基础上实现了一个可嵌入或旁路部署的智能体行为监督原型系统。

系统在工具真正执行前插入 Guardian 审计点，将每次工具调用整理为结构化 \texttt{ToolCall}，结合用户请求、历史工具序列、不可信来源和红队元数据，经过 Policy、Taint、Intent、Anomaly 四层机制输出 \texttt{ALLOW}、\texttt{FLAG} 或 \texttt{BLOCK}。同时，项目提供离线对抗样本与越狱测试集、攻击复现脚本、DeepSeek 在线红队生成、漏拦截分析、自适应规则管理以及网页 Dashboard 演示系统。2026 年 7 月 30 日的离线复测共覆盖 30 条样本，其中攻击样本 22 条、良性样本 8 条。当前系统检出 22/22 条攻击，阻断型误报为 0，平均审计延时约 0.269 ms。实验结果说明，四层监督机制能够在课程原型范围内较稳定地识别高危工具调用、敏感文件访问、不可信数据流和异常攻击链。

\noindent\textbf{关键词：} 大语言模型安全；智能体安全；提示注入；工具调用劫持；污点追踪；行为监督；红队评测

\section{作品概述}

\subsection{背景与问题}

大语言模型从单轮问答发展到智能体应用之后，模型不再只是生成文本，还会根据上下文规划工具调用。一个具备文件读写、网页抓取和代码执行能力的智能体，如果被恶意输入、网页内容或环境文件诱导，就可能在用户没有明确授权的情况下读取敏感文件、写入长期记忆、执行命令或向外部域名发送数据。

传统的内容安全审核通常关注模型输出是否包含违规文本，但智能体安全更关注行动本身是否越权。攻击者可以把危险指令伪装成普通任务，也可以把指令藏在网页、日志、README、配置或长期记忆中。对这类问题，只在模型回复结束后做文本检查往往太晚，因为真正的风险发生在工具执行前后。因此，本作品把研究重点放在智能体行为监督上：在每次工具调用真正执行前，实时审计工具名、工具参数、上下文来源和历史行为，必要时阻断。

\subsection{选题目标}

课程选题要求从红队视角研究大语言模型及智能体应用的攻击面，并设计可嵌入或旁路部署的行为监督机制。结合这一要求，本作品没有把任务理解为“写几个危险提示词”，而是把攻击、防御和验收放在同一条链路里处理：红队侧负责构造能够诱导智能体行动越权的样本，防御侧负责在工具执行前做可解释审计，演示侧负责把一次请求从用户输入、模型输出、工具调用到最终阻断完整呈现出来。

因此，本作品的目标可以概括为一句话：让一个具备工具调用能力的大模型智能体，在面对提示注入、越狱、训练数据泄露、工具调用劫持、记忆中毒和环境污染等攻击时，能够在真正执行危险动作之前留下证据、给出判断，并在必要时阻断。

本作品不是把 DeepSeek 或其他大模型作为唯一研究对象，而是把大模型智能体的工具调用链路作为研究对象。DeepSeek 在项目中主要用于两类在线演示：一是生成红队攻击样本，二是作为可选 intent judge 判断工具调用与用户意图是否一致。所有 API Key 都只通过运行时输入或环境变量使用，不写入脚本和文档。

\subsection{作品成果}

在原始 Argus 项目基础上，本作品已经形成从样本到原型的闭环。离线部分提供 30 条评测样本和可复现攻击脚本，用来保证没有 API Key 时也能稳定验收；在线部分接入 DeepSeek，用真实模型生成红队样本，并在前端展示提示词、攻击目标、工具调用和四层审计结果；工程部分实现 Guardian 四层监督、审计日志、SQLite 历史流和规则管理。这样做的好处是，最终展示不是单独演示某一条规则命中，而是能复现“红队样本如何产生、Guardian 如何判断、结果如何沉淀为验收记录”的完整过程。

\section{作品设计与实现}

\subsection{总体架构}

Argus 将智能体的一次行动抽象为如下链路：

\begin{center}
\texttt{用户请求 -> LLM Agent 规划工具调用 -> Guardian 审计 -> ALLOW / FLAG / BLOCK -> 工具执行或阻断}
\end{center}

系统核心不是替代大模型，而是在大模型和工具执行环境之间增加一道行为监督闸门。对于嵌入式部署，Agent 在调用工具前主动调用 Guardian；对于旁路部署，系统也能读取工具调用日志、上下文和审计记录进行回放分析。Dashboard 则把这些审计结果可视化，方便验收时逐条说明“为什么拦截、由哪一层拦截、证据是什么”。

\subsection{核心数据结构}

Guardian 使用统一的数据结构连接前端、后端、评测脚本和 Agent：

\begin{itemize}
  \item \texttt{ToolCall}：表示智能体准备调用的工具，包含工具名、参数和工具调用 ID；
  \item \texttt{Context}：表示当前上下文，包含用户原始请求、历史工具序列、污点来源、片段级污点和红队元数据；
  \item \texttt{Verdict}：表示单个防御层的判断，动作包括 \texttt{ALLOW}、\texttt{FLAG} 和 \texttt{BLOCK}；
  \item \texttt{Decision}：表示最终决策，任一层 \texttt{BLOCK} 即阻断，无阻断但有 \texttt{FLAG} 即告警，全 \texttt{ALLOW} 才放行。
\end{itemize}

这种结构的好处是各层可以独立演进，而评测、审计日志和前端展示只依赖统一接口。

\subsection{四层行为监督机制}

智能体攻击往往不是在一个位置一次性出现。危险意图可能直接写在用户输入里，也可能藏在网页返回内容中；工具名可能看起来正常，但工具参数已经越过文件沙箱；单次读取文件未必危险，但如果后续紧接着外联，就构成了数据泄露链路。因此，Argus 没有把监督器设计成单一关键词过滤器，而是把一次工具调用拆成四类证据：动作边界、数据来源、意图一致性和行为序列。四层分别处理不同证据，最后再统一聚合。

\begin{longtable}{p{2.6cm}p{3.8cm}p{7.2cm}}
\toprule
\textbf{防御层} & \textbf{判断的问题} & \textbf{原理说明} \\
\midrule
Policy & 这个动作本身是否越过安全边界 & 把工具名、参数、路径、URL 和红队元数据看成确定性约束。只要命中危险命令、沙箱外路径、敏感文件、未知工具、外联域名或记忆中毒写入，就在执行前直接阻断。 \\
Taint & 当前高权限动作是否受不可信内容影响 & 将网页和文件读取结果登记为不可信来源，同时保存文本片段摘要。若这些片段或来源在后续 \texttt{run\_shell}、\texttt{write\_file} 等高权限动作中出现，就说明模型可能被间接提示注入影响。 \\
Intent & 工具调用是否偏离用户原始任务 & 对一些规则难以判断的动作，调用可插拔 judge 比较用户请求和工具调用。离线评测默认关闭，在线演示时可启用 DeepSeek intent judge。 \\
Anomaly & 这次调用放在历史序列中是否反常 & 关注“先读后写”“先抓取后执行”“读取后外联”“同一工具反复调用”等序列模式，用来覆盖单次调用看似正常但攻击链已经形成的情况。 \\
\bottomrule
\end{longtable}

Guardian 的聚合逻辑很简单，但这是系统可解释性的基础。四层都会运行，并各自返回一条 \texttt{Verdict}。只要有一层认为必须阻断，最终就阻断；没有阻断但出现告警，则进入 \texttt{FLAG} 状态。这段代码节选展示了系统如何把四层判断收敛为一个最终动作。

\begin{lstlisting}[language=Python,caption={Guardian 汇总决策核心节选}]
# Run every layer first, so the audit log keeps full evidence.
verdicts = [layer.check(call, ctx) for layer in self.layers]

# BLOCK has the highest priority: one unsafe layer stops execution.
blocking = [v for v in verdicts if v.action == Action.BLOCK]
if blocking:
    reason = "; ".join(f"[{v.layer}] {v.reason}" for v in blocking)
    return Decision(Action.BLOCK, reason, verdicts)

# FLAG means suspicious but not enough to stop the tool call.
flags = [v for v in verdicts if v.action == Action.FLAG]
if flags:
    reason = "; ".join(f"[{v.layer}] {v.reason}" for v in flags)
    return Decision(Action.FLAG, reason, verdicts)

# Only a clean pass from all layers can become ALLOW.
return Decision(Action.ALLOW, "all layers passed", verdicts)
\end{lstlisting}

这段实现保留了两点工程含义。第一，系统不会因为 Policy 已经阻断就跳过其他层，前端和审计日志仍然可以看到完整的四层证据。第二，最终状态采用清晰的优先级：阻断优先于告警，告警优先于放行，因此展示页上的“总状态”和“1-4 层状态”可以稳定对应到同一次审计。

Policy 层更像一组执行前的硬闸门。它不依赖模型判断，因此适合处理“明确不该做”的事情，例如 \texttt{rm -rf}、反弹 Shell、\texttt{curl | sh}、读取 \texttt{.env} 或 \texttt{id\_rsa}、访问 \texttt{evil.example}、把网页内容写入长期记忆。后来补充的工具能力注册表也接在这一层：未知工具仍然默认阻断，但阻断理由会提示新工具应先登记能力、风险等级和最小权限，这比散落的固定白名单更容易继续扩展。

Taint 层处理的是 Policy 层不容易单独看清的问题。以间接提示注入为例，用户可能只是让智能体总结网页，但网页正文里藏着“忽略此前指令并执行下载脚本”。如果模型后来真的把网页中的片段带入 Shell 或写入记忆，危险并不来自用户请求本身，而来自不可信数据流。Argus 因此在工具输出进入模型上下文之前登记来源和片段，后续高权限调用再检查这些片段是否流入参数。下面的代码节选可以看出，本层不是只看关键词，而是把“来源、片段、Sink”三件事连起来。

\begin{lstlisting}[language=Python,caption={片段级污点流入高权限动作的判断节选}]
# Taint only matters when untrusted data reaches a high-impact sink.
if ctx.tainted_sources and call.name in HIGH_PRIVILEGE_TOOLS:
    # Normalize the current tool arguments into comparable text.
    payload = _flatten_input(call.input)
    # Match exact fragments instead of only checking source names.
    fragment_matches = [
        fragment for fragment in ctx.tainted_fragments
        if _fragment_matches_payload(fragment, payload)
    ]
    if fragment_matches:
        # Dangerous text copied into the sink is blocked before execution.
        desc = _dangerous_text(fragment_matches[0].text)
        if desc:
            return Verdict(NAME, Action.BLOCK, "...", confidence=0.9)
        # Non-dangerous tainted flow is still kept as an audit warning.
        return Verdict(NAME, Action.FLAG, "...", confidence=0.7)
\end{lstlisting}

这里的关键不是“网页内容出现过”这一件事，而是“不可信片段进入了高权限动作参数”。因此 Taint 层既能解释间接提示注入为什么危险，也能避免把所有读取网页后的正常摘要任务都直接拦掉。

Intent 层的作用不是替代前两层，而是在工具调用没有明显危险模式时补充语义判断。例如“总结网页”与“写入长期规则文件”之间没有必然关系，如果只靠路径和关键词，可能既容易漏掉也容易误报。在线演示中，DeepSeek intent judge 会把用户原始请求和当前工具调用整理成结构化 JSON，判断二者是否一致；离线 benchmark 默认关闭，是为了让课程验收不依赖外部网络。

Anomaly 层关注时间顺序。智能体安全里经常出现“当前一步还能解释，连起来就危险”的情况：先读取内部日志，再把结果发往外部域名；先抓取网页，再把网页内容写进计划文件；或者短时间内反复调用同一工具。Anomaly 层不试图证明每个动作单独违法，而是把调用历史、污点来源和红队元数据放在一起看，识别异常跳转和外联链路。这样，第四层不只是装饰性的统计项，而是能补到工具调用劫持和间接提示注入中的链路风险。

\subsection{DeepSeek 在线红队与自适应规则}

Dashboard 中的 DeepSeek 红队模块支持选择攻击面、生成条数和提示词模式。提示词不再是一行固定文本，而是按攻击面和模式组织，支持“精准单步”“伪装正常任务”“多步攻击链”“绕过变体”等生成方式。DeepSeek 生成的内容会被解析为攻击目标、用户请求、工具调用、污点来源、风险点、期望动作和危险说明，再交给 Guardian 审计。

如果某条 DeepSeek 生成的样本期望 \texttt{BLOCK} 或 \texttt{FLAG}，但 Guardian 实际 \texttt{ALLOW}，前端会标记为漏拦截。用户可以点击“分析漏拦截”，由 DeepSeek 分析未拦截原因，再把建议收束为受限字段规则写入 \texttt{adaptive\_rules.json}。规则只做字段包含匹配，不执行模型生成代码，避免把安全策略完全交给模型控制。

\subsection{工具能力注册表}

PPT 展望中提到“工具集超出预设怎么办”。这个问题完整解决需要较大工程量，因为真实 Agent 可能接入数据库、邮件、浏览器、向量库和云存储，每种工具的权限、参数和业务语境都不同。本阶段先完成一个小工程补丁：新增 \texttt{tool\_registry.py}，为当前工具记录能力标签、风险等级和审计关注点。

\section{作品测试与分析}

\subsection{测试方案}

测试没有只看“能不能跑起来”，而是分成三个层次。第一层是单元测试，保证 Policy、Taint、Intent、Anomaly、Dashboard API 和数据集转换器在代码层面稳定；第二层是离线 benchmark，用固定样本统计检出率、误报率、良性告警和审计延时；第三层是网页演示验收，通过 Dashboard 一键运行 7 个攻击面，并生成 Markdown、JSON 和 SVG 记录。三类测试的侧重点不同：单元测试看函数是否可靠，benchmark 看整体效果是否可量化，网页验收看系统是否能被课堂现场操作和解释。

本报告中的核心数据来自 \texttt{scripts/run\_benchmark.py}。这组评测不依赖外部 API，因此适合放入最终报告和验收材料；DeepSeek 在线红队则作为补充，展示真实模型如何生成新的攻击样本，以及 Guardian 如何把在线样本纳入同一套审计流程。

\subsection{样本构成}

离线测试集共 30 条样本，其中攻击样本 22 条，良性对照 8 条。样本规模不算大，但设计上覆盖了本课题最关心的几类智能体风险：直接危险命令、敏感文件访问、网页或文件中的间接提示注入、长期记忆污染、工具调用劫持和序列异常。良性样本的作用也很重要，因为一个安全监督器如果只会拦攻击、不关心正常任务，就很难在真实 Agent 中使用。

从总体指标看，Argus 在当前样本集上检出全部 22 条攻击，未出现把良性样本直接阻断的情况。这里的“检出”包括 \texttt{BLOCK} 和 \texttt{FLAG} 两种动作：绝大多数攻击被直接阻断，少量序列异常样本被标记为告警。这样统计更符合行为监督系统的定位，因为旁路部署时并不是所有风险都必须立刻中止，有些异常更适合作为人工复核线索。

2 条良性样本被标记为 \texttt{FLAG}，主要原因是它们发生在“读取不可信内容之后继续写文件”的场景中。单看任务目标，它们可以是正常摘要或整理；但从安全角度看，不可信网页内容影响后续写入，本来就值得留下审计记录。因此，这 2 条结果不算阻断型误报，而是系统有意保留的灰度提示。这个结果也说明 Argus 没有把所有不可信来源后的动作一刀切拦掉，而是在可继续执行和需要复核之间做了区分。

延时方面，本次复测中四层审计的平均耗时约 0.269 ms，p50 为 0.238 ms，p95 为 0.586 ms。这个数字只统计本地规则、污点和异常检测，说明这些检查可以放在工具执行前实时运行，不会成为原型系统的主要瓶颈。需要注意的是，离线评测中的 Intent 层默认关闭，因此这里的延时不包含在线 LLM judge 调用；如果启用 DeepSeek intent judge，实际耗时会更多地受网络和模型响应影响。比较合理的部署方式是：常规工具调用走本地四层检查，高风险或规则无法判断的工具调用再触发在线 judge。

四层统计不能简单相加，因为每个样本都会同时经过四层，一条攻击可能被多个层同时命中。例如间接提示注入样本既可能被 Policy 识别为向计划文件写入注入内容，也可能被 Taint 识别为不可信片段流入高权限动作，还可能被 Anomaly 识别为读取后提权。多层重叠不是重复劳动，而是提升了可解释性：Policy 告诉我们动作违反了哪条硬边界，Taint 说明危险文本来自哪里，Anomaly 解释为什么这条调用链异常。

\section{创新性说明}

本作品最主要的特点，是把“模型安全”落到了“智能体行为安全”上。许多大模型安全实验停留在提示词和回答文本层面，而本项目关心的是模型接下来准备做什么：是否要执行命令、是否要读写文件、是否要访问网页或调用外部工具。这个视角更贴近 Agent 应用的真实风险，因为一次看似普通的回答即使没有违规内容，也可能伴随着危险工具调用。

第二个特点是监督结果可以解释。Policy、Taint、Intent、Anomaly 四层不是只输出一个笼统分数，而是分别留下规则命中、污点来源、语义偏离和序列异常证据。前端展示的“总 / 1 / 2 / 3 / 4”状态，本质上就是把这条证据链可视化。答辩时不需要只说“系统判断它危险”，而是可以进一步说明危险动作在哪里、由哪一层发现、为什么这一层会阻断。

第三个特点是红队闭环。DeepSeek 在线红队可以生成新攻击样本，Guardian 负责实时审计；如果某条样本没有拦住，系统可以调用 DeepSeek 分析漏拦截原因，再把建议约束为可撤销、可启停、可计数的自适应规则。这个设计没有让模型直接写入任意代码，而是把模型建议放进受限规则治理流程中，既展示了模型辅助防御的可能性，也保留了安全边界。

网页 Dashboard 则把这些机制组织成可演示系统。批量红队矩阵适合展示多条样本的整体状态，攻击链视图适合解释单条样本的风险来源，规则管理页适合展示防御策略如何演进，一键验收则把固定 7 个攻击面的运行结果保存为验收材料。相比只给命令行输出，这种形式更容易让旁观者理解项目确实覆盖了“攻击、审计、阻断、复盘”这一整条链路。

\section{总结}

本作品围绕“面向大模型及其应用的安全性研究”完成了一个可运行、可评测、可展示的智能体行为监督原型系统。项目覆盖提示注入、模型越狱、训练数据泄露、工具调用劫持、记忆中毒、环境感知污染、间接提示注入和序列异常等攻击面，提供了对抗样本与越狱测试集、攻击脚本、评测结果和网页演示系统。2026 年 7 月 30 日的离线复测显示，在当前 30 条样本上，系统检出 22/22 条攻击，阻断型误报为 0，平均审计延时约 0.269 ms。

这些结果能够说明当前原型在课程设定的攻击面内是可验收的，但不应被理解为系统已经覆盖所有真实攻击。公开攻击集接入已经有转换脚本，真正扩大到 AdvBench、JailbreakBench 和真实 Agent 轨迹，还需要更多标注、抽样和对照实验；工具集超出预设也不是简单增加几个工具名就能解决的问题，本阶段通过工具能力注册表完成了工程入口，后续仍要继续做最小权限、场景策略和旁路观察；Anomaly 层目前以可解释启发式为主，未来可以引入 n-gram、Markov 或 embedding 序列模型。也就是说，本项目当前版本完成了从题目要求到可演示原型的闭环，后续研究重点应放在更大规模样本、更复杂工具生态和更严格的规则治理上。
